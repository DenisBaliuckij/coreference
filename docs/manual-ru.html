1. Назначение и ключевая идея стенда

Стенд автоматизирует исследовательский эксперимент по каскадной интеграции разрешения кореференции в построение семантического графа: сначала резолвер разрешает кореференцию в тексте, затем из полученного текста строится граф. На входе — корпус с золотой разметкой кореференции в формате CoNLL-U (нотация CorefUD), на выходе — качество разрешения кореференции и качество графа.

Ключевой инструмент — oracle-абляция. Для каждого документа граф строится по двум текстам:

  • oracle-граф — по тексту, в котором все упоминания каждой золотой цепочки заменены на форму её первого упоминания (без участия модели). Это верхняя граница: граф при идеальном разрешении кореференции;
  • predicted-граф — по тексту, обработанному реальным резолвером.

Разрыв между ними — «бюджет ошибок», вносимый этапом разрешения кореференции (гипотеза H1 диссертационного плана). Для корректного чтения этого разрыва стенд содержит два контрольных условия новое: NoResolution (текст не меняется — нижняя граница) и Gold (золотой текст ещё раз — потолок, достижимый при данной воспроизводимости бэкенда). Реальные резолверы располагаются между этими двумя точками; доля пройденного пути — «gap closed» (раздел 12).

2. Установка: Docker-образ (рекомендуется) и локальная установка

Docker новое

Каталог docker/ содержит Dockerfile и run.sh. Образ включает всё нужное для прогонов, ничего не устанавливая на хост: Python 3.11, spaCy 3.8 с en_core_web_sm/en_core_web_lg, WordNet для NLTK (распакованный — NLTK 3.10 не читает zip), udapi и официальный скорер CorefUD (зафиксированный коммит 4fd7b0e), CPU-версию PyTorch, sentence-transformers и зависимости LLMv2 (pymorphy3, razdel, scikit-learn, hdbscan), а также две модели эмбеддингов, загруженные при сборке (во время прогона сеть HuggingFace не нужна).

Контекст сборки — каталог, где рядом лежат coreference/ (этот репозиторий) и text-corpuses-processing/ (нужен каталог dags/; в образе он попадает в /text-corpuses-processing/dags — путь по умолчанию стенда):

experiments/coreference/
  Dockerfile  run.sh            # из coreference/docker/
  coreference/                  # git archive ветки cascade-experimental-stand
  text-corpuses-processing/dags/
  corpora/                      # корпуса (монтируются только для чтения)
  reports/                      # результаты

docker build -t coref-experiment:latest --build-arg BUILD_INFO="coreference <commit> ..." .
./run.sh tests                 # все тесты в контейнере
./run.sh smoke                 # сквозной прогон на data/corpora/sample_en_mini.conllu
./run.sh python -m pipeline.run_experiment ...

run.sh запускает одноразовые контейнеры (--rm) от имени пользователя 1000 с сетью хоста — чтобы --llm-endpoint http://127.0.0.1:8081/v1 доходил до llama-server, слушающего только 127.0.0.1. Монтируются ./corpora → /corpora (только чтение) и ./reports → /reports.

Локальная установка

  1. pip install -r requirements.txt — networkx, numpy, scipy, smatch, udapi, pytest.
  2. Склонируйте официальный скорер https://github.com/ufal/corefud-scorer, установите его зависимости и укажите путь к corefud-scorer.py в переменной COREFUD_SCORER. Без скорера прогоны резолверов, выдающих кластеры, завершаются ошибкой, а соответствующие тесты пропускаются.
  3. Положите text-corpuses-processing рядом (../text-corpuses-processing) или задайте TEXT_CORPUSES_PROCESSING_DAGS — путь прямо к его dags/.
  4. Для реальных прогонов: LapinLiass — en_core_web_sm; RuleBased — en_core_web_lg и WordNet; LLMv2 — torch, transformers, sentence-transformers и модели эмбеддингов; SpacyNeural — en_coreference_web_trf (только Python 3.8–3.10 и spaCy 3.4–3.5, поэтому в общий образ не входит).

4. Корпуса: английский GUM и русский RuCoCo новое

Сводный корпус CorefUD (репозиторий LINDAT) с хоста эксперимента недоступен — сайт отвечает HTTP 451 (юридическая блокировка); обходить её не следует. Поэтому английский и русский берутся из первоисточников.

Английский — GUM

https://github.com/amir-zeldes/gum, каталог dep/ — это же исходный корпус английской части CorefUD. Файлы уже содержат разметку Entity= (схема атрибутов GUM: GRP-etype-infstat-...) и читаются стендом без конвертации. Разбиение — официальное из splits.md; документы GUM_reddit_* исключаются (их текст в репозитории замаскирован подчёркиваниями):

ЧастьДокументовТокенов
train197~200 тыс.
dev30~28 тыс.
test30~28 тыс.
gentle_ood (внедоменный GENTLE)26~18 тыс.

Русский — RuCoCo

https://github.com/vdobrovolskii/rucoco, релиз v1.0.0: JSON с полями text, entities (символьные спаны упоминаний каждой сущности) и includes (расщеплённые антецеденты). Конвертация:

python -m pipeline.corpus.rucoco_convert RUCOCO_JSON_DIR OUTPUT_DIR

Токенизация — правиловый токенизатор spaCy для русского (без загрузки модели); предложения — sentencizer плюс границы абзацев, но никогда внутри упоминания (упоминания CorefUD не пересекают границу предложения). Синтаксиса нет (HEAD = 0), поэтому для RuCoCo используется только --coref-match exact. Расщеплённые антецеденты подсчитываются, но не записываются — официальный скорер их не оценивает. Результат v1.0.0: 3075 документов, ~1,22 млн токенов, 38 877 сущностей, 150 405 упоминаний, 0 несопоставленных упоминаний, 2978 расщеплённых антецедентов. Для экспериментов с LLM используется фиксированная выборка sample150 (150 документов, random.Random(20261005).sample по отсортированному списку файлов).

5. Первый запуск и полный эксперимент

  1. Соберите образ и проверьте его: ./run.sh tests (109 тестов), ./run.sh smoke (результат в reports/smoke_en/; на учебном примере все метрики равны 1,0).
  2. Английский эксперимент на тестовой части GUM (все резолверы, оба бэкенда, сопоставление по вершинам — стандарт CRAC): 
    ./run.sh python -m pipeline.run_experiment --corpus /corpora/en_gum/test --language en \
  --resolvers NoResolution,LapinLiass,LLMv2,Gold --graph-backends RuleBased,LLMv2 \
  --coref-match head --llm-endpoint http://127.0.0.1:8081/v1 --llm-model qwen3.8:27b-mtp-128k \
  --save-artifacts --output /reports/full_en_gum_test
  3. Русский эксперимент на выборке RuCoCo: 
    ./run.sh python -m pipeline.run_experiment --corpus /corpora/ru_rucoco/sample150 --language ru \
  --resolvers NoResolution,LLMv2,Gold --graph-backends LLMv2 --coref-match exact \
  --llm-endpoint http://127.0.0.1:8081/v1 --llm-model qwen3.8:27b-mtp-128k \
  --save-artifacts --output /reports/full_ru_rucoco_sample150
  4. Сводка с доверительными интервалами: 
    ./run.sh python -m pipeline.analysis.summarize /reports/full_en_gum_test \
  /reports/full_ru_rucoco_sample150 --out /reports/summary --bootstrap 1000
Долгие прогоны запускайте через nohup ./run.sh ... > logs/имя.log 2>&1 & — тогда обрыв SSH-сессии их не прерывает. Ориентиры по времени на qwen3.8 (27B) через llama-server: ~15 с на граф LLMv2 для документа RuCoCo, ~35–40 с для документа GUM.

6. Формат входного корпуса (CoNLL-U / CorefUD)

Файлы .conllu с атрибутом Entity= в колонке MISC. Поддерживаются однотокенные ((e1-person-1-new)) и многотокенные упоминания (открывающая и закрывающая скобки), несколько скобок в одном значении без разделителя (e1)(e2-loc-...), пустые узлы (N.1) для нулевой анафоры и несколько документов в файле (# newdoc). Текст восстанавливается по токенам с учётом SpaceAfter=No; упоминания на пустых узлах помечаются как нулевые и не подставляются в oracle-текст.

# newdoc id = sample1
# sent_id = sample1-1
1  John     John    PROPN  _  _  2  nsubj  _  Entity=(e1-person-1-new-1-sgl-1)
2  arrived  arrive  VERB   _  _  0  root   _  SpaceAfter=No
3  .        .       PUNCT  _  _  2  punct  _  _

# sent_id = sample1-2
1  He       he      PRON   _  _  2  nsubj  _  Entity=(e1)
2  left     leave   VERB   _  _  0  root   _  SpaceAfter=No
3  .        .       PUNCT  _  _  2  punct  _  _

Для официального скорера каждое предложение должно иметь # sent_id, а файл — заголовок # global.Entity; если заголовка нет (как в учебном примере), стенд добавляет стандартный eid-etype-head-other сам.

Не поддерживается: многословные токены (строки 3-4) — их форма отбрасывается при восстановлении текста; разрывные упоминания (e1[1/2]) — маркеры трактуются как часть идентификатора.

8. Резолверы, контрольные условия и бэкенды графа

ИмяЯзыкиЧто делаетКластеры (CoNLL F1)
NoResolution новоелюбойКонтроль-«пол»: текст без измененийнет
LapinLiassenПравиловый резолвер местоимений (spaCy en_core_web_sm + salience)да
SpacyNeuralenНейросетевой en_coreference_web_trf (вне Docker-образа, см. раздел 2)да
LLMv2любой язык с prompts/coreference_<lang>.txt (en, ru)LLM переписывает местоимения и указательные слова полными именаминет
Gold новоелюбойКонтроль-«потолок»: золотой текст и золотые кластеры. CoNLL F1 обязан быть 1,0 (проверка пути оценки); графовые метрики — шумовой потолок бэкендада
БэкендЯзыкиИсточник
RuleBasedenСинтаксический разбор spaCy (en_core_web_lg) + лемматизация WordNet; детерминирован
LLMv2en, ruLLM: извлечение троек по чанкам → нормализация → дедупликация (эмбеддинги) → сборка графа

Почему нужен Gold: LLM-бэкенд не вполне воспроизводим — один и тот же текст, извлечённый дважды, даёт немного разные графы. Поэтому oracle-граф против самого себя не даёт 1,0, и реальные резолверы надо сравнивать с этим потолком, а не с единицей.

9. LLM-компоненты через OpenAI-совместимый сервер новое

Встроенный клиент LLMv2 загружает модель в процесс эксперимента (по умолчанию Qwen2-1.5B на CPU). Клиент pipeline/llm/openai_client.py вместо этого отправляет те же промпты уже работающему серверу (llama-server, vLLM, /v1 Ollama). Выбранные значения и причины:

  • temperature 0 — воспроизводимость (встроенный клиент сэмплирует при 0,3);
  • 1024 токена ответа — встроенные 256 обрезают переписывание окна из 5 предложений (особенно на русском) и длинные списки троек, то есть портят именно сравниваемые тексты и графы;
  • без «размышлений» (enable_thinking = false) — промпты требуют прямого переписывания или JSON.

Параметры и расход токенов записываются в run_config.json. На общем сервере эксперимент занимает слоты наравне с другими пользователями: на хосте corpus-host каталогизатор документов уступает им все слоты, коллегам остаётся не меньше двух.

11. Метрики и официальный скорер CorefUD

Кореференция изменено

MUC, B³, CEAFe и CoNLL F1 (их среднее) считает официальный скорер CorefUD (скорер шейред-тасков CRAC, ÚFAL) — один раз на весь корпус (микроусреднение по документам), а не как среднее по документам; поэтому числа сопоставимы с опубликованными результатами. Синглтоны игнорируются (по умолчанию скорера), нулевые упоминания сопоставляются методом dependent.

Стенд пишет ответ резолвера как построчную копию золотого файла, в которой вся золотая кореференция удалена, а предсказанные кластеры записаны скобками CorefUD 1.0. Ключ (key.conllu) переписывается из золотых кластеров по тому же правилу (схема eid-etype-head-other, вершина упоминания — первое слово, чей синтаксический родитель вне упоминания). Иначе при head золото против самого себя давало на GUM CoNLL F1 = 0,53: в схеме атрибутов GUM нет поля вершины. Проверено: золото против золота = 1,0 на GUM test при всех трёх режимах и на всём RuCoCo при exact. Упоминания, пересекающие границу предложения, в CorefUD недопустимы: такие отбрасываются и подсчитываются (dropped_*).

РежимКогда упоминания совпадают
exactСовпадает весь набор слов
partialОтвет внутри золотого упоминания и содержит его вершину
headСовпадают вершины (стандарт CRAC; нужен синтаксис)

16. Частые вопросы и типичные ошибки

coreference_metrics: null у LLMv2 или NoResolution — это ошибка?

Нет: эти резолверы не выдают кластеры (раздел 8). Для них считаются только графовые метрики.

«CorefUD scorer not found»

Скорер не установлен или не задан COREFUD_SCORER. В Docker-образе он уже есть.

Скорер падает с «No global.Entity header found»

В ключе нет заголовка # global.Entity. Стенд добавляет его сам; при ручном запуске скорера добавьте строку # global.Entity = eid-etype-head-other в начало файла. Файл также должен оканчиваться пустой строкой.

Золото против золота меньше 1,0

Для кореференции такого быть не должно — это ошибка пути оценки. Для графа LLM-бэкенда это нормально: так измеряется его шумовой потолок (раздел 8).

Контейнер не достаёт до 127.0.0.1:8081

Запускайте через run.sh (сеть хоста). Проверка: curl 127.0.0.1:8081/v1/models на хосте.

Прогон LLMv2 идёт медленно

Каждый граф — десятки запросов к LLM (один на чанк из трёх предложений). Ориентиры — в разделе 5; ход виден в логе по строкам «Extracting triplets».

Почему нет испанского, хинди, корейского

Их данные с одинаковой разметкой есть только в CorefUD (LINDAT), недоступном с хоста эксперимента. Решение о языковом наборе принимается вместе с научным руководителем.
